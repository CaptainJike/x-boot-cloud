# AI 工具/MCP 模块职责说明

最后更新：2026-06-22

## 服务：ai-service 工具/MCP 子域

服务作用：
- 负责后台企业 AI 平台的工具注册元数据、后续工具鉴权配置、调用审计和 MCP 适配边界。
- MVP 阶段仍承载在 `ai-service`，不新建独立 Maven 模块；标准链路是 `admin-api -> ai-facade -> ai-service -> mapper`。

当前任务范围：
- 本轮只新增工具注册表、实体、Mapper、SQL 同步和表结构测试。
- 工具鉴权配置、工具调用审计日志、真实 HTTP 工具调用和 MCP Client/Server 适配均留给后续任务继续实现。
- 工具注册表只保存工具元数据、非密钥调用边界、请求/响应 Schema、允许主机、敏感字段和默认超时。
- 工具注册表不保存 API Key、Token、密钥明文或完整请求 Header。

业务能力：
- 管理工具的基础注册元数据，包括编码、名称、描述、工具类型、调用协议和启停状态。
- 记录 HTTP/MCP 等工具入口的非密钥配置，为后续后台管理接口、工作流节点引用和 MCP 适配提供统一注册来源。
- 记录请求参数 Schema、响应 Schema 和工具配置 Schema，为后续参数校验、表单生成和调用结果解释预留基础。
- 记录允许访问主机、敏感字段和默认超时，为后续工具执行安全控制提供注册级约束。

拥有数据：
- `ai_tool_registry`：已新增表，保存工具注册元数据、非密钥调用边界、Schema、允许主机、敏感字段、默认超时、版本号和启停状态。

提供的 Facade：
- 暂无；本轮仅新增数据模型和 Mapper。
- 后续如新增后台工具管理接口，应新增 `AiToolFacade` 或在明确边界后拆分工具注册、鉴权和审计 Facade。

消费的 Facade：
- 无新增跨服务 Facade 依赖。
- 后续工作流 HTTP 工具节点迁移为消费工具注册能力时，只能通过工具 Facade 或 ai-service 内部服务读取工具注册，不直接跨领域访问 Mapper。

HTTP 入口：
- `admin-api`：本轮无新增 Controller；后续新增后台工具管理接口时统一放在 `admin-api`。
- `app-api`：无；`app-api` 不作为本轮 Pig AI 后台平台 MVP 入口。

租户行为：
- `ai_tool_registry` 为行级租户数据，依赖 `TenantContextHolder` 和 MyBatis-Plus 租户插件隔离。
- 工具注册默认只对当前租户可见；特权租户可按现有租户插件规则绕过行级条件。
- 当前不支持匿名工具访问；如后续新增公开工具入口，必须先设计租户来源、访问令牌、限流和审计策略。

安全行为：
- 工具注册不保存密钥、Token、完整 Header 或外部系统敏感响应。
- 工具注册中的 `allowed_hosts` 和 `sensitive_fields` 只是注册级安全约束，实际执行时仍必须由工具调用服务再次校验。
- 后续后台接口应要求后台登录态，并使用 `AiTool:*` 权限码前缀。
- 后续工具鉴权配置必须单独建模，并考虑脱敏、密文存储或配置中心引用。

不负责：
- 不负责用户账号、角色、菜单、租户主数据或后台权限缓存。
- 不负责 C 端 app 用户体系和 C 端 AI 产品入口。
- 不负责本轮实现真实 HTTP 请求、MCP 协议适配、调用审计、重试、限流或定时调度。
- 不负责执行任意代码、脚本沙箱或非白名单网络访问。
